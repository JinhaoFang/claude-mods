# 0004: The band's agent-view figures come from tracked turn steps

context-band must show the context fill of whichever conversation is on screen, but the engine exposes no per-agent usage: `$.session.usage()` answers the main conversation only, so agent-view figures are accumulated from `turn.step` results — each step's reported request tokens stand for that agent loop's current context fill — while main-conversation figures keep the engine-native call. `turn.complete` alone was rejected because its per-turn sum overstates multi-step turns, and recomputing from `$.session.messages({ agentId })` on every view switch was rejected as heavy and a re-implementation of tokenization. The cost of this choice: an agent with no completed step in this process shows no reading, and the percent denominator for a model differing from the main loop's comes from a small table, since the engine reports no per-agent window.
